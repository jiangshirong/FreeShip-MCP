# 单位、坐标与数值含义

[English](numerics.md)

## 坐标和尺度

`scale_model` 可通过 `project_length_m`、`project_beam_m`、`project_draft_m`
在缩放网格后明确填写设计尺度。省略时，项目尺度随几何缩放。
填写项目尺度不会把实际水线尺度自动变成这些数值。
可选的 `x_offset_m` 在缩放后沿 x 轴平移网格及启用的标记，不改变艉垂线坐标基准，
也不移动已有交线；交线需要重新生成。

模型 x 轴向艏、y 轴为横向、z 轴向上。适配器沿用 FreeShip 项目中的艉垂线 `x=0`，
不会把网格的最小 x 当作艉垂线。船体几何可以超出垂线范围。

浮心的两种输入基准：

```text
lcb_ap_m = 距艉垂线的米数
lcb_ap_m = (0.5 + midship_forward_fraction) * length_m
```

比例为浮心相对船中的纵向距离除以项目船长，不是百分数。项目填写的主尺度、实际控制网格范围、
浸水范围和水线尺度各有含义，不能直接相互替代。

吃水从参与静水力计算的船体最低点向上量取。纵倾输入为艏艉吃水差，正值艏倾；艉端水面高度
为 `最低点 + 吃水 - 纵倾/2`，艏端为 `最低点 + 吃水 + 纵倾/2`。横倾使用度。

浮心坐标保留上游静水力坐标系：先扣除龙骨最低点 z，再按纵倾、横倾旋转。
因此 `vcb_m` 是该基准之上的高度，不是模型的绝对 z。`keel_model_z_m` 和
`centres_reference` 给出基准。无横倾和纵倾时，x 坐标与模型相对艉垂线的 x 一致。
`no_immersion=true` 时，中心位置中的零值是原生占位值，不代表已定义的浮心。

## 容积、质量及英制

原生算法先计算几何排水容积，使用密度及附体系数计算排水质量，然后把保存的容积乘以附体系数。
接口分开返回 `volume_geometry_m3` 和 `volume_corrected_m3`，防止重复乘系数。

对外单位统一为米、吨、平方米、立方米。英制模型坐标从英尺换算，密度从 lb/ft³ 换算，
长吨按 `1.0160469088` 换算成公吨；模型原单位及原密度同时保留。

上游设置函数的“公制转英制”使用非标准 `Lbs=0.44642857` 常数。适配器不调用它转换用户模型，
也不自动改写密度。已有英制模型应核对 `density_t_m3` 是否符合实际物理含义。

## Lackenby 船型变换

保持上游的前后半船剖面积分及纵向点变换，每半船 40 个区间。默认最多 15 次迭代。
收敛判据是 SAC 相对容积误差不大于 `1e-4`，浮心相对船长误差不大于 `5e-5`；
另保留上游绝对浮心误差不大于 `0.002` 个模型长度单位的条件。

`sac_lcb_length_relative_residual` 返回实际相对残差。
`sac_lcb_convergence_metric` 返回上游用于判断停止的量，满足绝对误差条件后会设为 `4.9e-5`。
未收敛时明确失败，不提交结果模型。

SAC 剖面积分与三维曲面静水力积分有数值差异。变换后再返回实际的排水量、浮心残差，以及
`hydrostatic_targets_within_native_tolerance`。SAC 收敛不保证这个标志为真。
程序不暗中追加缩放或放宽判据来使复核“通过”。

可选的 `block_coefficient` 是相容性检查：目标几何容积除以项目填写的 `L×B×T`，
必须与目标排水量、密度及附体系数一致，允许差为 `1e-4`。它不替换 FreeShip 可选择的
`fcActualData` 系数基准。

## 精度、交线与输出

上游数值类型是 IEEE-754 单精度。保留模型的细分精度设置，不提前按报告小数位舍入。
Excel 保存数值，其显示位数通过格式设置；序列化精度受电子表格数值格式限制。

交线使用原生曲面求交。DXF 沿用上游的 100 点采样及折角参数，排列为侧视、俯视和横剖视图。
空的端点站位保留位置，但不生成虚构曲线，所以站位数量可能大于非空曲线站位数量。

位置或吃水可使用显式列表，也可使用 `[起点, 终点, 间距]`。终点恰好位于网格上时才包含终点。
拓扑检查报告相邻法向、非流形边与原生破口候选点，不自动修补，也不保证排除全部曲面自交。

## JSON 传输和文件路径

原生请求与响应使用 UTF-8 JSON。中文原文与 JSON 的 `\uXXXX` 转义形式应表示同一路径。
模型目录和文件名支持 Unicode，与旧 FBM 文件的文本编码设置无关。
0.3.1 修复了固定版本 FPC 解析器对连续 Unicode 转义的截断问题，更新时应同时替换服务和计算引擎。
